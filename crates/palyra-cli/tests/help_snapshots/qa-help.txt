Validate, preview, and execute QA Lab scenarios

Usage: palyra qa [OPTIONS] <COMMAND>

Commands:
  validate         Validate QA Lab scenario manifests
  run-pack         Preview a deterministic QA pack from scenario schemas
  provider-compat  Validate provider compatibility fixtures
  gate             Run a QA Lab suite gate and maturity scorecard

Options:
  -h, --help
          Print help (see a summary with '-h')

Global Options:
      --profile <PROFILE>
          Use the named CLI profile from the local profile registry

      --expect-profile <EXPECT_PROFILE>
          Require the resolved active profile name to match this value

      --config <CONFIG_PATH>
          Use this palyra.toml config file

      --state-root <STATE_ROOT>
          Use this runtime state root directory

  -v, --verbose...
          Increase logging verbosity (-v => debug, -vv => trace)

      --log-level <LOG_LEVEL>
          Set diagnostic log verbosity

          [default: info]
          [possible values: error, warn, info, debug, trace]

      --output-format <OUTPUT_FORMAT>
          Select text, JSON, or NDJSON output for automation

          [default: text]
          [possible values: text, json, ndjson]

      --plain
          Disable styled terminal output

      --no-color
          Disable ANSI color output

      --allow-profile-mismatch
          Allow commands to continue when the selected profile differs from context

      --allow-strict-profile-actions
          Permit strict profile-scoped actions after explicit profile checks

Examples:
  palyra qa validate
  palyra qa validate --path qa/scenarios/text_run_basic.yaml
  palyra qa validate --path qa/scenarios --json
  palyra qa run-pack --tag p0 --json
  palyra qa run-pack --tag release_smoke --output artifacts/qa-pack-report.json
  palyra qa gate --suite qa/suites/pr_smoke.yaml --json
  palyra qa provider-compat --path qa/fixtures/provider_compat --json

Discoverability:
  `qa validate` checks QA Lab scenario manifests before runner or replay tooling consumes them.
  `qa run-pack` previews selected scenario schemas without executing the runtime.
  `qa gate` executes selected fixture scenarios through an isolated daemon runtime.
  `qa provider-compat` validates sanitized provider quirk fixtures and recovery expectations.
